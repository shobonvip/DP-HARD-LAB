## v0.5.9 皿リズム補正・皿コスト校正と単発5% HARD（現行）

皿ノーツの多さや最大速度だけではなく、押し引き間隔の複雑さを分けて扱う。拍に対する間隔の種類・変化・反復から局所複雑度を推定し、単純な規則連皿ではHARDで一部を取りこぼせる前提で反復・高速動作の負荷を軽くする。複雑な間隔列には認識負荷を加える。1.25拍を超える休止とテンポ境界をまたぐ区間はリズム複雑度の計算から除く。これにより、単純な16分皿が大量に続く譜面と、皿の押し引きが不規則に切り替わる譜面を区別する。補正係数は実プレイ成功率で未校正。

## v0.3 皿の接触・往復・指分担（旧版）

2026-09-27更新。ゲージ仕様・ミス生成・能力探索は変えず、皿を含む動作の負荷を修正しました。

- **鍵盤→皿／皿→鍵盤**：実際の位置履歴と、直前の同じ手の動作からの時間で移動負荷を計算します。皿専用の手の位置から鍵盤に戻る場合は、手全体の着地と皿担当指の移動を重複加算しません。
- **皿→皿**：接触する指と直前の皿時刻、押し引きの方向を保持します。接触が続く連皿では鍵盤との往復距離は0。最初を押しと仮定し、以降は押し／引きを交互にします。押しと引きの得意不得意は同一と仮定し、実際の回転方向を譜面から推定した表示ではありません。
- **切り返し**：仮の最小切り返し時間を85msとし、間隔Δtに対し max(0, 0.085/max(0.015, Δt) − 1) を加算。これより遅くても物量・基本皿負荷・活動蓄積は残ります。連皿間隔の変化にも小さな負荷を加えます。ターンテーブルの慣性や回転角度の物理再現ではありません。
- **接触の解除**：通常は皿間隔600msまで接触継続を仮定。皿担当指を鍵盤に使う、または残りの指で届く範囲を超えると接触を解きます。担当指を使わず、手の届く範囲の鍵盤を挟む場合は接触を保てます。600msは未校正のモデル定数です。
- **皿＋鍵盤**：薬指または小指を皿の担当候補として、鍵盤の指候補と同時に比較します。担当指と鍵盤指が重なる候補は高負荷、皿から鍵盤までの距離が手の広がりを超える候補は追加負荷。全指を皿位置へ移す処理を廃止しました。実際には手の側面など多様な取り方があり、この候補集合は限定的です。
- **長い皿保持**：BSSの保持中は接触指を予約し、終点を反転として扱います。保持の途中に架空の判定ノーツや往復ストロークは作りません。保持中の回転量・摩擦・HCN固有のゲージ挙動までは再現していません。

画面の「皿の総負荷」はv0.3の実際の入力負荷です。「皿への往復」「皿の切り返し」「皿と鍵盤の分担」を分けて表示します。どれも正規配置の動作平均で、最大瞬間負荷や実ミス率ではありません。「認識と指の動き」では推奨固定配置の負荷上位動作に皿の動作種別・押し引き・担当指を表示します。

修正前は DP-HARD-LAB-v2.html と data/table-v2.json に保存。推定HARDの☆換算は新モデルの難度別中央値から再計算するため、皿を含まない曲も表示値が変わる場合があります。距離・速度・指分担の係数は実プレイ未校正です。



## v0.2 認識・運動モデル（皿以外は継続、皿は上記に更新）

2026-09-27に需要負荷の計算を更新しました。以下のv0.1の需要負荷式は旧版の記録です。ゲージ、判定生成、能力探索、RANDOM戦略の集計は従来と同じで、入力するノーツごとの需要負荷を変更しています。

- **位置**：隣接レーン間隔を1とする2次元座標を使用。白鍵と黒鍵は前後に0.8ずらし、皿位置は右手換算x=9.5に仮置き。実測した筐体寸法ではありません。
- **指の履歴**：親・人・中・薬・小ごとに位置、最後に使った時刻、活動履歴を保持します。ほかの指を挟んだ場合も、その指が前回どこを押したかを追跡します。
- **移動**：距離dと目標幅Wに対して `0.035 + 0.045 log2(1+d/W)` 秒の移動時間を仮定し、打鍵回復時間・次の打鍵までに使える時間と比較します。薬指・小指の速度係数も仮置きです。[Fittsの運動距離と許容幅の研究](https://doi.org/10.1037/h0055392)に着想を得た近似であり、この式や係数をIIDXで実証したものではありません。
- **指割当**：最大12候補から、移動時間不足、指の重複、CN保持指の変更、手の広がり、次の動作への準備を含むコストで選択します。先読みは最大0.65秒かつ次の7グループまで、その中で次の同手鍵盤動作を参照します。全曲を見通す最適化や完全な人体シミュレーションではありません。
- **認識**：同じ同時押し、2点トリル、一定方向の階段にパターン軽減を適用。直近2秒の同形出現は再認しやすくし、配置の変化量とリズム間隔の変化には負荷を加えます。視線移動・脳活動・個人の学習履歴は再現していません。
- **協調動作**：同時押しは1つの協調動作＋追加指の負荷、全押しは手のひら候補として扱います。ゲージ判定ノーツ数は変えません。左右が同じ形かどうかも補助的に評価します。
- **皿と拘束**：鍵盤↔皿の2次元移動距離、使える時間、同時に届く必要のある範囲を評価します。CNを保持する指の割当変更を高コストにしますが、物理的な不可能性を厳密に排除する制約ソルバーではありません。
- **活動の蓄積**：指の活動が続くと小さな負荷を積み、休むと指数的に減衰させます。生理的な疲労の実測モデルではありません。

現行需要負荷は `(0.65×協調動作密度 + 1.3×移動負荷 + 0.7×手の広がり + 1.6×認識負荷 + 左右協調 + 活動蓄積 + 0.870×皿負荷/皿能力 + 0.35×拘束数) / 手の能力比`。皿係数以外は実プレイ未校正です。皿係数も外部順位統計への限定的な校正で、成功率の校正ではありません。旧版の物量・配置などの形態特徴も比較用に残しています。

画面には認識負荷、指移動負荷、手の広がり、左右協調、パターン再利用率、負荷上位の時刻と候補指割当を追加しました。ローカル版では手の広がりと先読み時間を変更できます。保存版は計算済み結果の閲覧のみです。

旧保存版は `DP-HARD-LAB-v1.html`、旧一覧は `data/table-v1.json` に保存。新旧で能力尺度も対象内順位も変わるため、数値の差をそのまま実力差とは解釈しないでください。

## 目的と現時点の意味

曲名からAIが難度を想像する方式ではなく、譜面の時系列 → 手ごとの処理負荷 → 判定確率 → HARDゲージ推移、という再現可能な計算を行います。人間の処理能力との対応は未校正です。実クリア率や個人の成功確率を保証するものではありません。

AIの役割はモデル設計、特徴量の仮説化、データ品質の検査、根拠を伴う説明です。初版の係数はAIが設計した仮説であり、AIが実際に運指を習得した結果でも、実プレイヤーから学習した重みでもありません。

## 対象と出典

対象：現行AC IIDX 34 ZINRAI収録、DP ANOTHER ☆5～9、DP全譜面 ☆10～11。TexTageのactblの曲・譜面双方の現行ACフラグで抽出します。LEGGENDARIAも含みます。取得時点を保存し、未公開・未解析を区別します。サイトの収録情報は公式との更新差があり得ます。

各譜面にTexTageへのリンクを保存しています。キャッシュはローカルで再利用し、新規取得時はURL・時刻・SHA-256を記録します。JavaScriptソースはevalせず、許可したデータ構文だけを独自解釈します。

譜面を刻み位置から秒へ変換します。基準は96刻み/拍、通常384刻み/小節ですが、曲別のLNDEFと小節長上書きを優先します。途中BPM変化は区間積分します。ノーツ数は譜面ページと一覧の双方で検証し、不一致は未解析にします。

この検査は完全な譜面一致を保証しません。同じノーツ数で位置だけ違う誤りを見つけるためには、画面や動画との位置照合も必要です。TexTage自身が微細なズレを省略する場合があると説明しています。

## 運指と特徴

右手の基本指配置を、1=親、2/3=人、4=中、5/6=薬、7=小とし、左手は左右反転します。拡張運指は親3・親5・中3/5/6・人4などを候補に含めます。同時押しの候補割当から、ホーム位置からの距離、同じ指の重複、直前ノーツからの同指移動、保持指の再割当のコストが小さいものを選びます。

これは局所探索です。長いフレーズ全体のビームサーチ、関節押し・べちゃ押し・運指切替の個人差は今後の課題です。候補に入れた指が、そのプレイヤーに実用可能かどうかも未知です。

| 特徴 | 計算 |
|---|---|
| 物量 | 最初から最後のノーツまでの平均notes/s |
| 片手ピーク | 各手の直前1秒間ノーツ数の最大値 |
| 配置 | 同時押しの指割当と直前の指移動の平均コスト |
| 連打 | 直前同手グループとの共通レーンと短い間隔 |
| 皿・着地 | 皿の有無、同時鍵盤の皿からの距離、300ms以内の鍵盤↔皿遷移 |
| CN拘束 | 同じ手で保持中のCN/BSS数 |
| 同時押し | 同時鍵盤数 |
| 局所難 | 負荷上位1%、2秒区間の最大負荷、平均との比率 |
| 左右差 | 各手のノーツ数、負荷 / 手ごとの能力比 |

需要負荷 `d = (0.62 × 片手密度 + 1.5 × 配置 + 連打 + 皿負荷 / 皿能力 + 同時押し + CN拘束) / 手の能力比`。

右利き標準は左0.90・右1.00、皿1.00です。右利きなら全員左0.90という実証はありません。皿と鍵盤で利き手傾向が一致しない人もいます。個別画面で変更してください。プロフィール変更は個別シミュレーションに作用し、保存済み一覧の全順位を変更するものではありません。

## ミスから生存確率へ

2026-09-27補正：皿・CN拘束のない12467同時押しは協調動作（運動密度の重み2.2）、7鍵全押しは手のひら動作（重み1.5、配置コスト0.3）として扱います。表示上のノーツ数や生のNPSは変えません。The Dirty of Loudnessの過大評価の指摘を受けた一般則で、同じ条件の他譜面・オプションにも適用します。係数は引き続き未校正です。

ノーツごとのミス確率を `sigmoid(−4.6 + (d − 能力)/1.35 + 0.8 × 相関ノイズ)` とします。相関ノイズは実時間で約0.7秒持続するAR型状態を使い、同時ノーツでは状態を共有します。これによりミスの塊を表現しますが、実測に基づく相関時間ではありません。

ミスの72%をPOOR・28%をBADと仮定し、ミス時8%で空POORを加えます。成功の7%をGOOD、残りをGREAT相当とします。空POORはBAD/POORの代わりではなく別イベントです。判定窓への物理的な打鍵時刻シミュレーションではありません。

同一seedで同じ結果を再計算できます。オプション比較は同一系列の乱数を使います。試行の95%区間はWilson区間で、有限回シミュレーションの誤差だけを表します。モデル構造・係数の誤りやプレイヤー個人差は含みません。

## 難度とオプション

固定8オプション：正規、左MIRROR、右MIRROR、両MIRROR、およびそれぞれのFLIP。FLIPで譜面を左右交換した後、プレイ側のMIRRORを適用します。

各オプションで80%完走に必要なモデル能力を二分探索します。初版は24試行・8段階探索・範囲0.25～32・刻み約0.124です。近い値の順位は不安定です。最小の能力を要求するものを固定推奨候補とします。選択後は別seedの48試行で再評価しています。最高能力でも目標未達の場合には探索打ち切り値となるため、結果監査で検知します。

H指数は、固定8オプションと後述のRANDOM2戦略のうち、最小の必要能力の対象内百分位0～100です。高いほど難しいという方向です。絶対難度ではなく、収録集合や解析できた曲が増えると変わります。H指数そのものは公式☆やノマゲ表の小数値ではなく、後述の推定HARD☆へ表示換算した値とも別に保持します。

RANDOMは左右別々に1～7鍵をシャッフルし、その配置を曲中固定します。スクラッチは固定です。両RANDOM8配置、FLIP＋両RANDOM8配置で、固定最良の必要能力における完走率を各24回測ります。平均、配置別P10～P90、独立試行を仮定した10回中1回以上の成功率 `1−(1−p)^10` を表示します。この10回は疲労、学習、連続プレイ環境などの依存を無視しています。

この平均・P10～P90・10回成功率は、2戦略を均等に混ぜた参考要約です。さらに難度比較用として、両RANDOMとFLIP＋両RANDOMを別々の戦略として扱い、それぞれ8配置に均等に試行を割り振り、64試行・8段階探索で80%完走の必要能力を求めます。別seedの128試行で再評価し、その試行由来の区間を表示します。固定最良より必要能力が低ければ、推奨候補とH指数にも反映します。

これは「毎回未知の配置を引いたときの単発80%」を、有限個の配置で近似したものです。5%版も同じ有限配置を使います。RANDOM全5,040²配置を網羅せず、実機乱数の分布も検証していません。小差の推奨は不安定で、片側RANDOM、R-RANDOM、S-RANDOMは未評価です。

## ノマゲ表との関係

[SNJ@KMZSの評価条件](https://zasa.sakura.ne.jp/dp/readme.php)はノマゲ・既知譜面・正規/逆正規。意図的な鍵盤/CN捨て・あんみつ・引っ越しは原則対象外で、皿捨ては例外として認めています。今回の目標とはゲージもオプションも異なります。

参照値は曲名正規化＋譜面種別＋公式レベルで照合します。不一致は空欄で、推測しません。表見出しは取得時点でSparkle Showerのままであり、ZINRAI新譜面や変更分に遅れがある可能性があります。

初版では参照値を表示するだけで、ミス確率やH指数には入れていません。将来はノマゲを弱い事前情報に使い、終盤回復と全曲生存の差を学習する設計が有望です。NORMAL譜面や下限付近の情報が薄い部分、未収録の曲は欠測として扱います。

## ereter.netの☆12統計

[ereter.netのレベル別統計](https://ereter.net/iidxsongs/analytics/perlevel/)から、掲載時点の`☆`、`EC diff`、`HC diff`、`EXH diff`と各クリア件数を取り込みます。譜面名と譜面種別で照合し、752譜面中742譜面に対応しました。照合できない譜面は空欄のままです。保存スナップショットは `data/ereter-hard-stats.json` にあります。

ereter値は曲別の需要やミス率へ直接代入しません。共通の皿係数・動作負荷係数の選定には、ソフランを除いたereter HC順位を使います。調整用と確認用の曲を分けますが、同じ外部母集団への校正であり、実プレイ成功率を検証したものではありません。ereterの☆・HC diff、公式☆、本ツールの推定☆は別の尺度です。

## 実用的な難易度表にするための校正

1. 多様な実力のプレイヤーから、曲ID・オプション・成功/失敗・全試行回数・日付・可能なら失敗時刻と区間BPを収集。クリア成功例だけを集めない。
2. 同じプレイヤーの総合能力、左右能力、皿、運指の習熟差を分ける。プレイヤー能力とミス確率の切片は同時に自由推定すると識別できないため、一方の尺度を固定する。
3. 曲単位・プレイヤー単位・時期単位の保留データでBrier score、対数損失、成功率の校正曲線、順位の対一致率を測定。同曲の別オプションが学習と評価へ漏れないようにする。
4. ノマゲだけ、総ノーツ数だけ、平均密度だけの基準と比較。皿・配置・局所難・相関ミスがどれだけ改善したかを確認する。
5. プレイヤーおよび曲で再標本化した不確実性と、ゲージ値・手のサイズ・運指モデルの感度を示す。十分な根拠がない曲は保留枠へ。
6. 実測で尺度を固定してから、ハードの段階ラベルや「10.8相当」などの対応を決める。0.01刻みの数値の見た目だけで精度を装わない。

実績入力の初期形式は `docs/play-logs.example.json`。データがない段階では確定値・校正済みと表示しません。

## 推定HARDの☆表示

公式難度ごとに解析済み譜面の必要能力中央値を求め、その値を同じ☆に対応させます（例：公式☆10の中央値→☆10.0）。80%版と5%版は別々に基準を作る。隣接する基準間は線形補間します。10譜面未満の難度は基準から除外するため、現在の基準は☆7〜12です。基準外は端の傾きで外挿し、☆12超も☆12.1、☆12.6のように小数1桁で表示します。☆5未満だけは下限表示にまとめます。CSVは両方の値を保持します。この表示尺度は実プレイで校正していません。

これは表示尺度の変更で、シミュレーション・順位・推奨オプションは変えません。☆10.5は必要能力が☆10と☆11の中央値の中間という意味で、公式評価やノマゲ難易度表の10.5と同義ではありません。元のH指数は詳細とCSVに残します。基準値と標本数はtable.jsonのstarScaleに保存します。公式難度はHARDの正解ではないため、この換算も実プレイで未校正です。
