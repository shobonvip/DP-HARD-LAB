# DP HARD LAB

保存データをgzip化し、HARD保存版を129.9→27.9MB、練習保存版を33.0→8.4MBに軽量化しました。データは自動展開して読み込みます。[容量・GitHub保存の説明](docs/STORAGE.md)。現在版のソースとデータをまとめるには `npm run package:github`。Git履歴を含まないZIPをartifacts/へ出力します。

[練習譜面集](DP-PRACTICE.html)を追加しました。サーバーでは `/practice.html`。☆7～9 NORMAL/HYPERを1,493譜面追加し、既存分を含む4,114譜面から体力・テクニック・皿・指定運指・同時押し・階段・混フレなど14テーマを抽出します。[集計方法](docs/PRACTICE.md)。

IIDX 34 ZINRAIのDP譜面を読み取り、配置負荷とHARDゲージの生存シミュレーションで比較するローカル研究ツールです。

v0.6.1では、皿の成分を鍵盤向けの負荷軽減から保護し、連皿が続く時間と休憩による回復を追加しました。学習133・確認27譜面で候補を比較し、確認側の順位相関0.708→0.793、順位差17.52→15.10ポイントを確認。BPMは曲共通値から譜面内のテンポ情報に切り替え、ソフランの誤分類も修正しました。ソフラン攻略とHCN継続判定の再現は未対応です。[今回の比較と攻略コメントによる確認](docs/SCRATCH_ENDURANCE.md)。

v0.6.0では、手全体と指の動作頻度に共通する負荷の重複を軽減し、混色同時押し・担当指の切り替えに準備負荷を加えました。縦連専用の負荷と指の回復時間は保持し、CN保持中の指を架空の再打鍵として数える不具合を修正しています。非ソフラン☆12の160譜面を曲名単位で学習125・確認35に分け、学習側だけで係数を選定。確認側の順位相関は0.736→0.788、平均絶対順位差は16.30→14.62ポイントでした。実プレイ成功率の校正ではありません。[比較と配置難の分析](docs/MOTOR_PLACEMENT.md)。

対象は現行AC収録の☆5～9 ANOTHERと☆10～12のNORMAL / HYPER / ANOTHER / LEGGENDARIA。TexTageの取得時点の収録フラグから抽出しています。外部サイトに譜面データのない曲は一覧に残り、未解析と表示します。公式収録リストとの全件照合は未実施です。

☆12には[ereter.netのレベル別統計](https://ereter.net/iidxsongs/analytics/perlevel/)と、[SNJ@KMZSのDP非公式ノマゲ表](https://zasa.sakura.ne.jp/dp/run.php)を別枠で併記します。保存時点の☆12 752譜面中、ereterは742譜面、ノマゲ表は742譜面を照合しました。`☆11.6`～`☆12.7`のノマゲ値、ereterの`HC diff`、HARDクリア件数のほかEC/EXHのdiffと件数も詳細・CSVに含めます。外部統計はDP-HARD-LABの推定値とは別の尺度です。該当データがない譜面は空欄です。

**研究版です。H指数は実プレイで校正した難易度ではなく、ノマゲの11.xなどとは互換性がありません。**

v0.5.9では、先読み範囲内の同色の流れとフレーズ反復を認識し、全体物量・片手密度・速い連続動作・階段・縦連を分けます。規則的な同色階段は習熟で軽減し、隣接階段やホーム運指を崩す階段には別負荷を加えます。皿はノーツ数や最大速度だけで難しくせず、規則的な高速連皿をHARDの許容を見込んで軽くし、複雑な押し引きリズムには認識負荷を加えます。打鍵時刻から判定を計算し、早打ち・遅れ、連打のズレの持ち越し、BADの連鎖を扱います。あんみつは個別再試行で有効にできます。係数、判定窓、優先順は実プレイ成功率やLM実機で未校正です。[周囲の配置・打鍵時刻の仕様](docs/CONTEXT_TIMING.md)と[人間工学モデル](docs/ERGONOMICS.md)を参照してください。

皿の身体コストは、ereter HC diffを照合できる非ソフラン☆12から皿負荷の分布に沿って360譜面を抽出し、学習173・確認187譜面に分けて校正しました。確認群で最良だった得意度1.15相当、すなわち従来の約87%の重みを標準に採用しています。ソフラン83譜面は係数選定に使っていません。曲別補正ではありません。

v0.5.9では、皿枚数や最大速度に加えて押し引き間隔の複雑さを見ます。単純な規則皿はHARDの取りこぼし許容を見込んで軽くし、複雑な皿リズムには認識負荷を加えます。保留187譜面で比較した軽減係数0.35が最良でした。実プレイ成功率そのものへの校正ではありません。

同時皿は左1・2・3鍵を親／人で分担、4鍵は限界付近、5・6・7鍵は無理皿として扱います（右は左右反転の仮定）。無理皿の通常タップは、移動時間を鍵盤の早打ちと皿の遅打ちに配分し、元の判定時刻で評価します。個別画面で皿の遅打ち量も指定できます。

v0.4では、ホーム運指（1親23人4中56薬7小）への習熟、拡張運指・階段・桂馬への慣れを、身体側の負荷から分離しました。鍵盤と皿はmm座標で扱い、押せる面積、指の干渉、皿上の円弧移動、仮定した抵抗と押し引きの力を評価します。個別画面で慣れ・寸法・力を調整できます。

LIGHTNING MODELを想定しますが、座標は互換機の図面と仮置きを含み、LM実機で測定した値ではありません。人体・筐体の厳密な物理再現ではなく、係数も未校正です。値の根拠と制約は [人間工学モデル](docs/ERGONOMICS.md) を参照してください。

旧版は `DP-HARD-LAB-v1.html` ～ `DP-HARD-LAB-v5.html` に保存しています。全譜面を更新する場合は `npm run human` → `npm run h5` → `npm run h5:compile` → `npm run tempo` → `npm run analyze` → `npm run export`。比較レポートは現在のモデルで計算したH5保存先を `--source` で指定し、別バージョンの混在を検査します。

## 起動

**見るだけなら `DP-HARD-LAB.html` をブラウザで開いてください。サーバー・AI・追加インストールは不要です。** 検索、並び替え、譜面詳細、保存済みシミュレーションを閲覧できます。新しい条件で再計算する場合のみ以下のローカル版を使います。

Node.js 20以上で、フォルダ内で次を実行します。

```sh
npm install
npm start
```

ブラウザで http://127.0.0.1:4173 を開いてください。既に生成された表はそのまま閲覧できます。

この作業環境では同梱の新しいNodeを使っています。Windowsでシステム側の古いNodeに起因する問題が出る場合は `start.ps1` をPowerShellで実行してください。

## 別PC・GitHubからの復元

`data/charts/`（再計算用の譜面）と `data/cache/`（取得元のキャッシュ）はGitの対象外です。保存版と計算済み結果の閲覧はそのまま使えますが、サーバーで条件を変えて再試行するには、`npm install` の後に `npm run restore` を実行してください。保存済みの対象一覧・解析成功記録に合わせてTexTageから直列取得し、ノーツ数を照合します。対象一覧は更新せず、途中で止まった場合は同じコマンドで再開できます。

取得キャッシュがない場合も、`analyze` は同じ曲名・譜面種別・公式難度の保存済みノマゲ参考値を引き継ぎます。新しいノマゲ表を取得した場合は、その内容を優先します。

現行モデルの計算済み結果から一覧と保存版を作り直すだけなら、`npm run analyze` → `npm run export` で完了します。復元した譜面と保存済み特徴量の照合は `npm run audit -- --verify-features` で行えます。作業状況と残作業は `docs/WORK_STATUS.md` に記録します。

## 更新・再計算

```sh
npm run collect
npm run human
npm run h5
npm run h5:compile
npm run analyze
npm test
npm run audit -- --verify-features
npm run export
```

- `collect` はキャッシュを再利用し、外部リクエストは直列・最短400ms間隔。途中失敗したリクエストは次回再実行できます。
- 外部ソースを取り直す場合は `npm run collect -- --refresh`。全件の再取得になるので通常は不要です。
- `human` は固定配置とRANDOM戦略の両方を計算します。途中で止まっても同じコマンドで再開できます。その後の `analyze` は計算済み結果を一覧・CSVに反映し、`export` が保存版を更新します。従来の `analyze` → `random` → `analyze` も利用可能です。
- `h5` は全解析済み譜面の単発5%結果を計算し、`h5:compile` が公開用の要約へまとめます。モデル版を変えた場合は80%版と同様に再計算してください。
- 保存した同じモデル版の結果は再利用します。モデルの係数を変更したらモデル版も変更するか `npm run analyze -- --force` で再計算します。
- ノマゲ表は `node scripts/normal-reference.mjs` で更新できます。曲名・譜面種別・公式難度を一致条件として照合します。

## できること

- 実譜面をノーツ列に変換。可変BPM・変拍子・CN/BSS端点を読み取り、ページと曲一覧のノーツ数に照合。
- 片手密度、配置コスト、皿・着地、連打、同時押し、CN拘束を抽出。
- 右利き仮定で正規・左右MIRROR・FLIPの8組み合わせを比較。
- 両RANDOMおよびFLIP＋両RANDOMを各8配置サンプリング。配置は曲中固定、スクラッチは移動しません。
- BAD / POOR / 空POOR、30%補正、成功打鍵回復、連続ミスの相関を含むHARD生存シミュレーション。
- 安定80%と単発5%の必要能力・H指数・公式難度中央値による参考☆、難所の時刻、ゲージ曲線、CSV一覧を表示。
- 個別画面で能力、左手比率、皿の得意度、運指、固定オプションを変えて256回再試行。

## 重要な制約

HCNの継続回復・減少、CN保持中の取りこぼし、BSSの持続動作、微細なズレ、ソフランでのHS操作、見切り力、手のサイズ、あんみつ・皿捨て・引っ越しは十分にモデル化できていません。指候補は局所的なコスト比較で、全譜面を通じた最適運指探索ではありません。該当譜面を含め、全スコアは仮説です。

H指数は固定8オプションと両RANDOM / FLIP＋両RANDOMを、単発80%完走に必要な能力で比較した仮指数です。H5指数は同じ候補の単発5%版です。独立20回で1回以上成功する確率は約64%ですが、疲労・学習・実機RANDOM全配置は含みません。RANDOMは各8配置だけの標本なので推奨は不安定です。片側RANDOM / R-RANDOM / S-RANDOMは今後の拡張対象です。

実プレイ記録は未取得なので、モデルの実用精度を測定したとは言えません。ノマゲ参考値を正解ラベルとしてハードの精度を主張することもしません。
